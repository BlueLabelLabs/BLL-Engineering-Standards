## Preferences

- Framework: **React Native** by default (**Expo** is fine); drop to **native** (Kotlin/Android, Swift/iOS) only when there's a specific need (e.g. device hardware or kiosk/industrial constraints). **Never Flutter.**
- Targets: **iOS and Android both** by default; single-platform only when specifically requested.
- Distribution: **App Store + Google Play**.
- Backend: a standard **server-side** backend (FastAPI REST — see the `server-side` pack).
- Auth: per `universal-baseline` (Auth0 / Firebase).

## Selection guidance

- Go native only for a concrete driver (device hardware, kiosk/industrial constraints, as in a ruggedized plant-floor app); otherwise React Native.
- Backend, data, auth, and monitoring follow the `server-side` and `universal-baseline` packs; the provider pack supplies hosting and managed services.
- Client conventions (state, structure, testing) are below the architecture barrier — see `references/conventions/mobile.md`.
