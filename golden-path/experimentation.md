## What this changes

This is **not a production build**. The "technical approach" is an **experimentation plan**, not a system architecture: define the question, run experiments to answer it, and reach a decision. Hold architectural commitment to a minimum until the experiments resolve the unknowns.

Most BlueLabel experimentation is **agentic / LLM-centric** — prototyping how LLMs and agents can solve a problem across a domain. ML model training is the **exception, not the default**.

## Preferences

- Focus: **agentic / LLM experimentation** — try different prompt/agent strategies, models, retrieval/RAG approaches, and tool designs; evaluate which best solves the problem across the target domain. Composes with `agentic-system`.
- Tooling: **Jupyter notebooks** for rapid prototyping, data exploration, and analysis; **LangSmith** for tracing and evaluating LLM/agent approaches against the success criteria.
- ML model training (PyTorch / MLflow / GPU, per `ml-training`) **only when the experiment is genuinely a model-training problem** — the exception, not the default.
- Infrastructure is **lightweight and throwaway** — don't stand up production architecture; use the minimum needed to run the experiments.
- The effort is **time-boxed** with clear checkpoints.
- The deliverable is **findings + a recommended approach** (and a go/no-go decision), not a deployed system.

## Selection guidance

- **Defer production architecture decisions** — the experiments exist to resolve those unknowns. The production build is a separate, later effort the findings inform (feeding a development-stage architecture / TAR).
- For agentic experiments, capture: the approaches/strategies to try, the evaluation set + criteria, and the decision each gate informs — not a stack and topology.
- Recommended artifacts: experiment plan, hypothesis & success-criteria list, evaluation rubric, findings & recommendation.
- A validated PoC becomes a separate production build later — usually a normal `agentic-system` (or `web-application`) architecture.
